Mock Oracle Health EHR API

Screen pop, patient lookup and FHIR-style endpoints for Genesys Cloud demos. All data is fictional.

Base URL: https://YOUR-HOST. Endpoints marked key require x-api-key: <API_KEY> or Authorization: Bearer <API_KEY> when the server is started with API_KEY set. Phone numbers can be in any format (tel:+13125550142, 312-555-0142); the last 10 digits are matched.

1. Screen pop by URL

GET/pop?<params>

Opens the EHR, finds the patient and starts an interaction banner (call timer, identity check, wrap-up). One match opens the chart; several matches show a picker; none offers registration.
ParamMeaning
phone / aniCaller number
mrn, fin, patientIdExact identifiers (take priority over phone)
lastName + dobDemographic match (dob as YYYY-MM-DD)
conversationId / gcConversationIdGenesys conversation ID; logged with the call. With server-side Genesys credentials configured and no phone given, the server looks up the caller's number from Genesys.
queue, direction, mediaType, intentShown in the banner. intent picks the chart tab (billing → Account, appointment → Visits, refill → Medications, results → Results)
tabForce a chart tab: summary, problems, medications, results, documents, allergies, visits, careteam, activity, account, histories
embed=1Compact layout for an iframe (auto-detected when framed)
view=classicPowerChart-style chart instead of the new Oracle Health EHR look
agent, personaSet the agent email this browser listens for; persona (access, care, provider, billing) used if nobody is signed in
Unsubstituted template text like {{Call.Ani}} is ignored, so a missing variable degrades to a search screen instead of an error.

2. Screen pop by API (push)

POST/api/screenpop key

Pushes a pop to every open EHR browser signed in as agent (Server-Sent Events). Use "agent": "*" to pop on all open browsers. 
curl -X POST https://YOUR-HOST/api/screenpop -H "Content-Type: application/json" -H "x-api-key: $API_KEY" \
  -d '{"phone":"tel:+13125550142","agent":"taylor.nguyen@lakeviewhealth.example","conversationId":"c1d2...","queue":"Patient Access","intent":"Billing question"}'
Response: the lookup result below plus screenPopId and deliveredTo (number of browsers that received it).

GET/api/screenpop/events?agent=<email>

Server-Sent Events stream the EHR uses to receive pushes (event: screenpop).

GET/api/screenpop/recent

Last 50 pops received.

4. EHR workflow endpoints

GET/api/patients?q=|phone=|mrn=|fin=|dob=|lastName=|firstName=|email=|memberId=

Patient search (summaries).

GET/api/patients/{id}

Full chart: demographics, allergies, problems, medications, vitals, results, encounters, documents, care team, activity log, account, appointments.

POST/api/patients

Register: firstName, lastName, dob required; optional sex, phone, email, addressLine, city, state, zip, language, payer, plan, memberId, group.

PATCH/api/patients/{id}

Update phones, email, address, language, preferredName, insurance, emergencyContact, portal.

GET/api/slots?providerId=&specialty=&from=YYYY-MM-DD&days=10

Open appointment slots.

POST/api/patients/{id}/appointments

Book: providerId, start (from a slot), type, reason, visitMode, conversationId. 409 if the slot was taken.

PATCH/api/appointments/{id}

Reschedule or change status: start, providerId, status (Confirmed, Arrived, Completed, Cancelled, No Show).

GET/api/schedule?providerId=pr-1&date=YYYY-MM-DD

Provider day schedule.

POST/api/patients/{id}/activities

Log a contact (what the wrap-up button does): method, direction, outcome, durationMin, note, conversationId, queue, createdBy.

POST/api/patients/{id}/prescriptions

New or renewed prescription: name, sig, refills, pharmacy, renew.

POST/api/patients/{id}/payments

Post a payment: amount, method. Returns new balance and confirmation number.

POST/api/patients/{id}/documents

Sign a note: title, type, text, author.

GET/api/messages   PATCH/api/messages/{id}

Message Center inbox.

GET/api/providers   /api/users   /api/config   /api/health

Reference data and health check.

POST/api/admin/reset

Restore the demo data (also happens automatically each day and on restart).

GET/api/genesys/conversations/{conversationId}

Server-side Genesys lookup of the customer participant's number, then patient match. Needs GENESYS_CLIENT_ID, GENESYS_CLIENT_SECRET, GENESYS_REGION.
